# 2026-10 third-party audit — closed-out summary

A static code review of this repository at commit `49d8730f` (2026-09-27) was delivered on
2026-10-08: six revisions, every file carrying code, configuration or LLM-facing text read, about
150 findings, each labelled VERIFIED (repro executed or lines cited), INFERRED or UNVERIFIED. The
application was never started by the reviewer and no integration test was run — several findings
were therefore checked live here before being accepted (X-TENANT1 was proved real across two
mission machines; ENV1, TF1, GIT1, MID1 and X-TENANT3 reproduced as described).

The full report, its remediation kit and the per-finding tracker contain repro payloads and stay
local (`audit-oct26/`, gitignored). This page is the committed record: what the audit concluded,
what was done about it, and what is still open. The working plan with the full reconciliation
table is [`docs/plans/audit-oct26-remediation-plan.md`](../plans/audit-oct26-remediation-plan.md);
each fix has a row in [`docs/security/findings.md`](../security/findings.md).

## What the audit concluded

The security story — *agents are untrusted, the daemon is trusted, tenants are isolated* — was
documented but not enforced, in three ways:

1. **The daemon was a confused deputy.** It ran as `magi-operator` with the cluster-wide
   `MONGODB_URI` and LLM keys, and performed file, git and job operations on paths and trees that
   agents or tenants control (GIT1, TF1, RS2, MS1, AR1, JOB1).
2. **Any signed-in user could reach platform secrets without an agent.** `${VAR}` expansion ran
   on tenant-supplied config (ENV1); team-file paths traversed out of the mission (TF1 → CHAIN-A).
3. **Spend containment was opt-in** and several LLM paths were unmetered.

Two secondary themes: stored schemas had drifted from their readers with no contract tests
(STATS1, CK-STALE, MR1), and LLM-facing text promised features that did not exist (SCHED2, OV1,
TPL4). The audit's own root-cause analysis is the part that shaped the response: everything a
machine enforced held (lint, tests, the one existing doc-vs-code test); everything that relied on
an author remembering to "pause and reason" drifted.

## What changed in how the code is maintained

The remediation kept the audit's point that a rule without an enforcement is a wish:

- `npm run verify` (build, lint, typecheck, unit tests with per-package coverage floors,
  tripwires, structure ratchet) runs in the pre-push hook and as the one CI gate both deploys wait
  on; `verify:quick` runs on every Claude Code stop.
- `scripts/audit/tripwires.sh` fails on the specific patterns behind the worst findings
  (`process.env` in config parsing, raw HTML sinks, path joins on agent-controlled input,
  unexplained spawns, git outside `safe-git.ts`, type-system escapes, raw mailbox inserts); its
  allowlist carries an owner and a reason per entry and may only shrink.
- `docs/security/trust-boundaries.md` answers, for every privileged operation, which of its inputs
  a less-trusted actor can write and what guards it; a row with a less-trusted writer and no guard
  is a finding.
- One commit per finding, test first (failing on the parent, passing after), with the findings
  table, threat model and resilience document updated in the same commit.
